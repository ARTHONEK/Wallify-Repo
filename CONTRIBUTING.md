# Как добавить обои в каталог Wallify

Спасибо, что хотите выложить свои обои. Ниже — всё, что нужно, чтобы PR прошёл проверку с первого раза.

Техническая часть (события движка, палитра, хранилище настроек, локальный сервер) описана в [WALLPAPER_API.md](WALLPAPER_API.md). Здесь — только правила каталога.

---

## 1. Подготовьте комплект

Создайте папку `wallpapers/<id>/`. Идентификатор `<id>` — строчные латинские буквы, цифры и дефис: `my-cool-wallpaper`, `neon-grid-2`. Он же становится именем папки и именем ZIP-архива.

Минимальный комплект:

```text
wallpapers/my-cool-wallpaper/
├── manifest.json     # обязателен
├── index.html        # точка входа
├── README.md         # показывается на странице комплекта
└── cover.png         # обложка карточки
```

**Обложка.** Соотношение 9:16 (например, 720×1280) или квадрат 500×500. Форматы: `png`, `jpg`, `webp`. Лучший вариант — скриншот с устройства. Если под рукой его нет, сгенерируйте заглушку:

```bash
python3 scripts/make_covers.py
```

**README комплекта.** Каталог показывает его на странице обоев, но понимает только ограниченную разметку: заголовки `#`, `##`, `###`, `**жирный**`, `` `код` `` и абзацы через пустую строку. Списки и таблицы отрисуются простым текстом. HTML экранируется.

---

## 2. Заполните `manifest.json`

```json
{
  "name": "My Cool Wallpaper",
  "description": "Короткое описание для карточки в каталоге.",
  "author": "Nickname",
  "version": "1.0.0",
  "minAppVersion": ">=1.0.0",
  "cover": "cover.png",
  "main": "index.html",
  "settingsPath": "settings/index.html",
  "useGyroscope": false,
  "isLite": false
}
```

- `useGyroscope` без значения `true` означает, что сенсор не будет зарегистрирован вообще — гироскопные обои останутся неподвижными.
- `isLite: true` ставьте, только если обои действительно экономные: мало объектов, никаких `blur` и `box-shadow` на пол-экрана. Пользователи фильтруют каталог по этому признаку.
- `minAppVersion` укажите явно. Если используете возможность, появившуюся в конкретной версии Wallify, поднимите планку.

---

## 3. Индекс создаст GitHub

Не редактируйте `index.json`: после merge GitHub сам возьмёт данные из имени папки и
`manifest.json`, добавит запись в каталог и поставит правильную ссылку на релиз.

ZIP тоже соберётся автоматически и попадёт в постоянный релиз:

```text
https://github.com/YouRooni/Wallify-Repo/releases/download/bundles/<id>.zip
```

---

## 4. Проверьте себя

```bash
python3 scripts/generate_index.py
python3 scripts/validate_catalog.py
```

Проверка гоняется в CI на каждом PR. Она сначала собирает временный индекс, затем
ловит битый JSON, дубли `id`, несуществующие пути, ошибки манифеста и ссылки на
внешние ресурсы.

Ошибки роняют сборку, предупреждения — нет, но их стоит разобрать.

---

## 5. Требования к коду обоев

**Запрещено:**

- майнинг, скрытая нагрузка на процессор, любой вредоносный код;
- обфускация — код должен быть читаемым при ревью;
- сбор и отправка данных пользователя;
- обращения к сети. Обои работают офлайн; всё нужное кладите в комплект.

**Обязательно:**

- обрабатывать `wallpaperPause` и `wallpaperResume` — иначе анимация продолжит крутиться и жечь батарею;
- считать время через `performance.now()`, а не через число кадров: движок останавливает цикл, когда обои невидимы;
- не создавать объекты в цикле отрисовки.

**Про разрешение канваса.** Не уменьшайте канвас «для производительности». Приложение уже растеризует страницу в масштабе из настройки «Качество рендеринга» (по умолчанию 80 %). Собственный коэффициент 0.8 поверх этого даст 64 % от разрешения экрана и заметно мыльные края.

**Про касания.** Проброс касаний в настройках приложения можно выключить. Если обои построены на `touchstart`, напишите об этом в `README.md` комплекта — иначе с выключенным переключателем они выглядят сломанными.

---

## 6. Обновление уже опубликованных обоев

Поднимите `version` в `manifest.json` — индекс и дата обновления изменятся
автоматически. Имя (`name`) менять нельзя: по нему определяется, что это те же
самые обои.
