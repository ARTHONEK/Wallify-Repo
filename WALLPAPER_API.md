## 1. Что такое Wallify

Wallify — движок живых обоев для Android, где обои представляют собой обычную HTML-страницу.
Приложение регистрирует системный `WallpaperService`, поднимает внутри него `WebView`,
загружает туда вашу страницу и покадрово переносит её на поверхность обоев.

Ключевые следствия из такой архитектуры:

- Вам доступен весь современный веб: CSS-анимации, `canvas`, SVG, `fetch`, шрифты, видео.
- Страница живёт постоянно, а не открывается по запросу. Экономия ресурсов — ваша забота.
- `WebView` в движке **не присоединён к окну**. Часть браузерных механизмов ведёт себя иначе,
  чем во вкладке браузера. Подробности в разделе [Ограничения движка](#12-ограничения-движка).
- Между обоями и приложением есть двусторонний мост: метаданные системы внутрь,
  пользовательские настройки наружу и обратно.

Комплект обоев — это просто папка с `index.html`. Никакой сборки, компиляции и подписи
не требуется.

## 2. Быстрый старт

Создайте папку внутри директории обоев Wallify и положите туда два файла.

**`manifest.json`**

```json
{
  "name": "Hello Wallify",
  "description": "Минимальный пример живых обоев",
  "author": "Ваше имя",
  "version": "1.0.0",
  "main": "index.html"
}
```

**`index.html`**

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <style>
    html, body {
      margin: 0;
      height: 100%;
      overflow: hidden;
      background: #141218;
    }
    #dot {
      position: absolute;
      width: 120px;
      height: 120px;
      border-radius: 50%;
      background: #6750A4;
      transition: background-color 0.4s ease;
    }
  </style>
</head>
<body>
  <div id="dot"></div>

  <script>
    const dot = document.getElementById('dot');
    let t = 0;

    function frame() {
      t += 0.02;
      const w = window.innerWidth;
      const h = window.innerHeight;
      dot.style.left = (w / 2 + Math.cos(t) * w * 0.3 - 60) + 'px';
      dot.style.top  = (h / 2 + Math.sin(t) * h * 0.2 - 60) + 'px';
      requestAnimationFrame(frame);
    }
    frame();

    // Палитра системы приезжает событием, а не сразу при загрузке скрипта
    window.addEventListener('wallpaperUpdate', (e) => {
      const c = e.detail.accentColors;
      document.body.style.background = c.background;
      dot.style.background = c.primary;
    });
  </script>
</body>
</html>
```

Откройте приложение, вкладка «Обои», потяните список вниз для обновления, выберите комплект
и нажмите «Применить».

## 3. Структура комплекта обоев

Директория обоев Wallify выбирается пользователем один раз через системный выбор папки (SAF).
Каждая подпапка первого уровня — отдельный комплект.

```
Директория обоев Wallify/
├── .nomedia                     создаётся автоматически
├── My Wallpaper/
│   ├── manifest.json            описание комплекта
│   ├── index.html               точка входа
│   ├── cover.jpg                обложка в списке
│   ├── icon.png                 запасной вариант обложки
│   ├── README.md                показывается в каталоге
│   ├── assets/
│   │   ├── style.css
│   │   ├── app.js
│   │   └── texture.webp
│   ├── settings/
│   │   └── index.html           экран настроек обоев
│   └── user_files/              картинки, добавленные пользователем
└── Another Wallpaper/
    └── index.html
```

### Как движок ищет файлы

| Назначение | Порядок поиска |
|---|---|
| Манифест | `manifest.json`, затем `wallpaper.json` |
| Точка входа | значение `main` из манифеста, по умолчанию `index.html` |
| Обложка | `cover` из манифеста, затем `cover.jpg`, `cover.png`, `cover.webp` |
| Иконка | `icon` из манифеста, затем `icon.png`, `icon.jpg`, `icon.webp` |
| Настройки | `settingsPath` из манифеста, затем `settings.html`, затем `settings/index.html` |

Имена файлов сопоставляются **без учёта регистра**. Манифест необязателен: без него комплект
получит имя папки и значения по умолчанию.

Файл `.nomedia` создаётся в корне директории обоев и в папках, куда попадают пользовательские
файлы, чтобы галерея не индексировала ресурсы обоев.

## 4. manifest.json

```json
{
  "name": "Material 3 Shapes",
  "description": "Плавающие фигуры в палитре системы",
  "author": "Rooni",
  "version": "1.2.0",
  "minAppVersion": ">=1.0.0",
  "cover": "cover.jpg",
  "icon": "icon.png",
  "main": "index.html",
  "settingsPath": "settings/index.html",
  "useGyroscope": false,
  "isLite": false,
  "animationDuration": 3.0,
  "animationDurationUnlock": 2.5,
  "animationDurationScreenOn": 1.2,
  "animationDurationScreenOff": 0.4,
  "animateOn": "both"
}
```

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | string | имя папки | Отображаемое название. Также становится именем папки при установке из архива |
| `description` | string | — | Описание в карточке комплекта |
| `author` | string | — | Автор |
| `version` | string | `1.0.0` | Версия комплекта. По ней определяется наличие обновления в каталоге |
| `minAppVersion` | string | — | Требование к версии приложения, см. [раздел 14](#14-совместимость-версий) |
| `cover` | string | — | Путь к обложке относительно папки комплекта |
| `icon` | string | — | Путь к иконке, используется если нет обложки |
| `main` | string | `index.html` | Точка входа |
| `settingsPath` | string | — | Путь к странице настроек |
| `useGyroscope` | boolean | `false` | Включает поток событий акселерометра. Без него сенсор не регистрируется вообще |
| `isLite` | boolean | `false` | Пометка «энергоэффективные». Влияет на фильтр в каталоге и приезжает в метаданных |
| `animationDuration` | number | `3.0` | Произвольная длительность в секундах, передаётся в метаданных |
| `animationDurationUnlock` | number | `2.5` | То же, для сценария разблокировки |
| `animationDurationScreenOn` | number | `1.2` | То же, для включения экрана |
| `animationDurationScreenOff` | number | `0.4` | То же, для выключения экрана |
| `animateOn` | string | `both` | `unlock`, `screen_on` или `both` |

Поля `animation*` и `animateOn` движок не интерпретирует. Он просто передаёт их в метаданные,
а как их использовать — решаете вы. Это сделано для того, чтобы длительности анимаций жили
в манифесте, а не были зашиты в код страницы.

## 5. Как файлы попадают в WebView

Внутри приложения работает локальный HTTP-сервер на `127.0.0.1`. Он читает файлы напрямую
из папки, выданной пользователем через SAF, и раздаёт их обоям.

### Адреса

| Кто загружает | Адрес |
|---|---|
| Активные обои | `http://127.0.0.1:PORT/index.html` |
| Превью в приложении | собственный сервер на отдельном порту, тоже с корня |
| Экран настроек обоев | собственный сервер на отдельном порту, тоже с корня |

Порт назначается динамически. Сначала пробуется `8088`, если занят — берётся любой свободный.
**Не зашивайте номер порта в код.** Пользуйтесь относительными и абсолютными путями:

```html
<img src="assets/logo.png">          <!-- относительный, работает всегда -->
<img src="/assets/logo.png">         <!-- абсолютный, тоже работает -->
<img src="http://127.0.0.1:8088/…">  <!-- так нельзя -->
```

Превью и экран настроек получают отдельный сервер именно для того, чтобы папка раздавалась
с корня. Благодаря этому абсолютные пути ведут себя одинаково во всех окружениях.

### Возможности сервера

- `ETag` и `304 Not Modified`. Повторные запросы к неизменённым файлам не перекачивают тело.
- `Cache-Control: no-cache` — браузер переспрашивает, но при совпадении `ETag` берёт из кэша.
- `Range` для частичной загрузки. Нужно для перемотки видео и аудио.
- `Access-Control-Allow-Origin: *` на своих файлах.
- `/favicon.ico` отдаётся как `204 No Content`.
- Пути с `..` отклоняются с `403`.

### Типы содержимого

Сервер определяет `Content-Type` по расширению:

```
html htm            text/html; charset=utf-8
js mjs              application/javascript; charset=utf-8
css                 text/css; charset=utf-8
json                application/json; charset=utf-8
txt md              text/plain; charset=utf-8
xml                 text/xml; charset=utf-8
png apng            image/png
jpg jpeg            image/jpeg
gif                 image/gif
svg                 image/svg+xml
webp                image/webp
avif                image/avif
ico                 image/x-icon
mp4 m4v             video/mp4
webm                video/webm
ogv                 video/ogg
mov                 video/quicktime
mkv                 video/x-matroska
mp3                 audio/mpeg
ogg opus            audio/ogg
m4a                 audio/mp4
flac                audio/flac
wav                 audio/wav

woff                font/woff
woff2               font/woff2

```

Всё остальное отдаётся как `application/octet-stream`.

### Внешняя сеть

Обои могут обращаться в интернет: погода, курсы валют, любые публичные API. Ограничения
обычные для веба — сервер должен отдавать корректные CORS-заголовки, иначе `fetch`
заблокируется.

Разрешён и смешанный контент: страница по `http://127.0.0.1` может грузить ресурсы по `https`.

## 6. JavaScript API

После загрузки страницы движок внедряет глобальный объект `window.WallpaperEngine`.

Важно: **на момент выполнения вашего скрипта объекта ещё нет.** Он появляется после
`onPageFinished`, вместе с событием `wallpaperEngineReady`. Пишите код так, чтобы он работал
и без моста — это же обеспечивает работоспособность страницы в обычном браузере при разработке.

```js
// Правильно
window.addEventListener('wallpaperEngineReady', (e) => {
  init(e.detail);
});

// Тоже правильно: с запасным значением
function getSpeed() {
  if (window.WallpaperEngine) {
    return window.WallpaperEngine.getSetting('speed', 'normal');
  }
  return 'normal';
}

// Неправильно: упадёт при первом выполнении скрипта
const speed = window.WallpaperEngine.getSetting('speed', 'normal');
```

### window.WallpaperEngine

| Метод | Возвращает | Описание |
|---|---|---|
| `metadata` | object | Последний известный снимок метаданных |
| `getMetadata()` | object | Запрашивает метаданные заново, синхронно |
| `getSetting(key, default)` | string | Значение настройки. **Всегда строка** |
| `saveSetting(key, value)` | void | Сохраняет настройку и уведомляет движок |
| `getAllSettings()` | object | Все настройки комплекта разом |
| `importFile(accept)` | Promise\<string\> | Открывает выбор файла, отдаёт `blob:`-ссылку |

Пример:

```js
const engine = window.WallpaperEngine;

const count = parseInt(engine.getSetting('shapeCount', '6'), 10);
engine.saveSetting('shapeCount', 8);

const all = engine.getAllSettings();
console.log(all); // { shapeCount: "8", speed: "fast" }
```

### Низкоуровневый мост

Под `WallpaperEngine` лежит объект `window.AndroidBridge` с методами `getMetadata`,
`getSetting`, `saveSetting`, `getAllSettings`. Пользуйтесь высокоуровневой обёрткой:
она работает и там, где моста нет.

## 7. Метаданные

Полная структура объекта, который приезжает в `event.detail` и возвращается из `getMetadata()`:

```json
{
  "theme": "dark",
  "accentColors": {
    "primary": "#D0BCFF",
    "secondary": "#CCC2DC",
    "tertiary": "#EFB8C8",
    "surface": "#1D192B",
    "background": "#141218",
    "surfaceContainer": "#211F26"
  },
  "screen": "home",
  "isUnlocked": true,
  "device": {
    "model": "Pixel 8",
    "manufacturer": "Google",
    "androidVersion": 35,
    "appVersion": "1.0.0"
  },
  "isLite": false,
  "animationDuration": 3.0,
  "animationDurationUnlock": 2.5,
  "animationDurationScreenOn": 1.2,
  "animationDurationScreenOff": 0.4,
  "animateOn": "both"
}
```

| Поле | Значения | Описание |
|---|---|---|
| `theme` | `light`, `dark` | Текущая тема системы |
| `accentColors` | object | Палитра, см. ниже |
| `screen` | `home`, `preview`, `settings` | Где сейчас выполняется страница |
| `isUnlocked` | boolean | `false`, когда активен экран блокировки |
| `device.model` | string | Модель устройства |
| `device.manufacturer` | string | Производитель |
| `device.androidVersion` | number | Уровень API, например `35` |
| `device.appVersion` | string | Версия Wallify |
| `isLite`, `animation*`, `animateOn` | — | Значения из вашего манифеста |

Значение `screen`:

- `home` — обои работают на устройстве, а также в превью внутри приложения;
- `preview` — открыт системный выбор обоев, идёт предпросмотр до применения;
- `settings` — код выполняется на странице настроек комплекта.

### Палитра Material You

Цвета приходят строками `#RRGGBB` без альфа-канала.

| Ключ | Назначение |
|---|---|
| `primary` | Основной акцент |
| `secondary` | Вторичный акцент |
| `tertiary` | Третичный акцент |
| `surface` | Поверхность |
| `background` | Фон |
| `surfaceContainer` | Приподнятая поверхность, `surfaceContainerHigh` в терминах Material 3 |

Откуда берутся значения:

- **Android 12 и новее** — динамическая схема Material You, извлечённая из обоев пользователя.
  Отдельные наборы для светлой и тёмной темы.
- **Android 11 и старше** — фиксированная эталонная палитра Material 3 (фиолетовая).

Палитра кэшируется в памяти и пересобирается при смене темы или конфигурации.

Практическое замечание: `background` и `surfaceContainer` в тёмной теме отличаются очень слабо,
порядка `#141218` против `#211F26`. Фигура, залитая `surfaceContainer` поверх `background`,
без обводки почти неразличима. Если вам нужен контраст, берите `primary` или добавляйте
обводку.

## 8. События

Все события приходят на `window` как `CustomEvent`, полезная нагрузка лежит в `detail`.

| Событие | Когда | `detail` |
|---|---|---|
| `wallpaperEngineReady` | Мост внедрён, страница готова | метаданные |
| `wallpaperUpdate` | Любое изменение состояния | метаданные |
| `wallpaperUnlock` | Устройство разблокировано | метаданные |
| `wallpaperScreenOn` | Экран включился | метаданные |
| `wallpaperScreenOff` | Экран выключился | метаданные |
| `wallpaperThemeChange` | Сменилась светлая/тёмная тема | метаданные |
| `wallpaperPause` | Пользователь поставил обои на паузу | — |
| `wallpaperResume` | Пауза снята | — |
| `wallpaperGyroscope` | Данные акселерометра | `{ pitch, roll, x, y, z }` |
| `wallpaperOffset` | Пролистывание рабочих столов | `{ xOffset, yOffset }` |
| `wallpaperFileImported` | Пользователь добавил файлы на странице настроек | `{ paths: [...] }` |

### Порядок при запуске

```
загрузка страницы
  → выполняется ваш скрипт (WallpaperEngine ещё нет)
  → wallpaperEngineReady
  → wallpaperUpdate
  → wallpaperUnlock          если устройство разблокировано
```

### Что происходит при включении экрана

```
ACTION_SCREEN_ON   → wallpaperUpdate + wallpaperScreenOn
ACTION_USER_PRESENT→ wallpaperUpdate + wallpaperUnlock
ACTION_SCREEN_OFF  → wallpaperUpdate + wallpaperScreenOff
```

`wallpaperUpdate` приходит всегда, а специфическое событие — дополнительно. Если вам достаточно
общего обработчика, слушайте только `wallpaperUpdate`.

### Глобальная функция triggerAnimation

Если на странице объявлена глобальная функция с таким именем, движок вызывает её при каждом
обновлении метаданных. Удобно для перезапуска вступительной анимации.

```js
function triggerAnimation() {
  document.body.classList.remove('intro');
  void document.body.offsetWidth; // перезапуск CSS-анимации
  document.body.classList.add('intro');
}
```

### Пауза и возобновление

Пользователь может остановить обои кнопкой в приложении. Обязательно обработайте это,
иначе цикл анимации продолжит работать вхолостую.

```js
let paused = false;

window.addEventListener('wallpaperPause',  () => { paused = true; });
window.addEventListener('wallpaperResume', () => {
  if (paused) {
    paused = false;
    frame();          // важно: перезапустить цикл
  }
});

function frame() {
  if (paused) return; // выходим, не планируя следующий кадр
  draw();
  requestAnimationFrame(frame);
}
```

Обратите внимание на подводный камень: если из `frame()` выйти без вызова
`requestAnimationFrame`, цикл прекратится навсегда. Возобновлять его нужно явно
в обработчике `wallpaperResume`.

## 9. Хранилище настроек

Каждый комплект получает изолированное хранилище. Ключ хранилища выводится из имени папки:
оно приводится к нижнему регистру, а всё, что не `a-z`, `0-9`, `_` или `-`, заменяется на `_`.
Настройки одних обоев недоступны другим.

```js
// Значения всегда строки, приводите типы сами
engine.saveSetting('speed', 'fast');
engine.saveSetting('shapeCount', 8);        // сохранится как "8"
engine.saveSetting('enabled', true);        // сохранится как "true"

const count   = parseInt(engine.getSetting('shapeCount', '6'), 10);
const enabled = engine.getSetting('enabled', 'false') === 'true';
```

`saveSetting` дублирует значение в `localStorage` страницы и отправляет движку сигнал
перечитать настройки. Живые обои в ответ получают `wallpaperUpdate`, поэтому изменение
со страницы настроек применяется без перезапуска.

Для сложных структур используйте JSON:

```js
engine.saveSetting('palette', JSON.stringify({ a: '#fff', b: '#000' }));
const palette = JSON.parse(engine.getSetting('palette', '{}'));
```

Не храните в настройках изображения в виде `data:`-URL. Это мегабайты base64 в системном
хранилище на каждую картинку. Для файлов есть механизм из следующего раздела.

## 10. Экран настроек обоев

Если в комплекте есть `settings/index.html` (или файл, указанный в `settingsPath`), в карточке
обоев появляется кнопка настроек. Страница открывается в отдельном экране приложения, с тем же
мостом и тем же хранилищем, что и сами обои. В метаданных `screen` равен `settings`.

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <style>
    body { font-family: system-ui, sans-serif; padding: 16px; color: #E6E1E5; }
    label { display: block; margin: 16px 0 8px; }
  </style>
</head>
<body>
  <label for="speed">Скорость анимации</label>
  <select id="speed">
    <option value="slow">Медленно</option>
    <option value="normal">Обычно</option>
    <option value="fast">Быстро</option>
  </select>

  <label for="count">Количество фигур: <span id="countValue">6</span></label>
  <input id="count" type="range" min="2" max="20" value="6">

  <button id="pick">Выбрать фоновое изображение</button>

  <script>
    window.addEventListener('wallpaperEngineReady', () => {
      const engine = window.WallpaperEngine;
      const speed = document.getElementById('speed');
      const count = document.getElementById('count');
      const countValue = document.getElementById('countValue');

      speed.value = engine.getSetting('speed', 'normal');
      count.value = engine.getSetting('shapeCount', '6');
      countValue.textContent = count.value;

      speed.addEventListener('change', () => engine.saveSetting('speed', speed.value));
      count.addEventListener('input', () => {
        countValue.textContent = count.value;
        engine.saveSetting('shapeCount', count.value);
      });

      document.getElementById('pick').addEventListener('click', () => {
        engine.importFile('image/*');
      });
    });

    // Файлы копируются в комплект, обратно приходят относительные пути
    window.addEventListener('wallpaperFileImported', (e) => {
      const paths = e.detail.paths;      // ["user_files/import_1730000000000.jpg"]
      window.WallpaperEngine.saveSetting('background', paths[0]);
    });
  </script>
</body>
</html>
```

### Импорт пользовательских файлов

Обычный `<input type="file">` тоже работает, но правильный путь — `importFile`. Он открывает
системный выбор, **копирует выбранные файлы в папку комплекта** (`user_files/`) и присылает
событие `wallpaperFileImported` с относительными путями.

Сохраняйте именно относительный путь. Тогда в обоях его достаточно подставить как есть:

```js
const bg = engine.getSetting('background', '');
if (bg) {
  document.body.style.backgroundImage = `url("${bg}")`;
}
```

Такой файл переживает перезагрузку, попадает в экспортируемый архив и не раздувает
хранилище настроек.

Поддерживаемые расширения при копировании определяются по MIME: `png`, `jpg`, `webp`, `avif`,
`gif`, `svg`, `webm`, `mp4`, `mov`, `mkv`. Неизвестный тип сохраняется как `.jpg`.

### Диалоги

`alert()` и `confirm()` на странице настроек показываются как системные диалоги Material.
В самих обоях `alert()` подавляется молча — показывать диалог поверх рабочего стола нельзя.

## 11. Жизненный цикл и производительность

### Настройки приложения, влияющие на обои

| Настройка | Диапазон | По умолчанию | Что делает |
|---|---|---|---|
| Частота кадров | 15 — частота экрана | 60 | Как часто движок переносит страницу на поверхность |
| Качество рендеринга | 50—100 % | 80 % | Страница растеризуется в уменьшенном разрешении и растягивается |
| Касания | вкл/выкл | вкл | Проброс нажатий с рабочего стола в страницу |
| Экономия энергии | вкл/выкл | вкл | В режиме энергосбережения частота падает до 1 кадра в секунду |
| Аппаратный рендер | вкл/выкл | выкл | GPU вместо процессора, Android 10+, только при качестве 100 % |

Важно: «Частота кадров» ограничивает частоту **переноса** картинки на обои, а не ваш
`requestAnimationFrame`. Если движок работает на 30 кадрах, а вы рисуете 60 — половина
кадров уйдёт впустую. Ориентироваться на конкретное значение из страницы нельзя, оно
пользователю доступно для изменения.

Качество рендеринга ниже 100 % означает, что страница растеризуется в уменьшенное разрешение.
Мелкий текст и тонкие линии станут мягкими. Учитывайте это: линия толщиной в один пиксель
при 50 % исчезнет.

### Состояния

```
Экран включён,  обои видимы   → кадровый цикл работает
Экран выключен                → цикл остановлен, сенсоры отключены
Открыто приложение            → обои невидимы, цикл остановлен
Ручная пауза                  → цикл остановлен, событие wallpaperPause
Энергосбережение              → 1 кадр в секунду, сенсоры отключены
```

Когда обои невидимы, ваш `requestAnimationFrame` браузер тоже приостановит. Не рассчитывайте
на непрерывное течение времени: считайте дельту через `performance.now()`, а не число кадров.

```js
let last = performance.now();

function frame(now) {
  const dt = Math.min((now - last) / 1000, 0.1); // ограничиваем прыжок после паузы
  last = now;
  update(dt);
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

### Рекомендации по нагрузке

- Не создавайте объекты в цикле отрисовки. Сборщик мусора на обоях особенно заметен.
- Тяжёлые эффекты вроде `blur` и `box-shadow` на больших областях стоят дорого в программном
  рендеринге. Предпочитайте заранее отрисованные текстуры.
- Останавливайте всё лишнее по `wallpaperScreenOff`, возобновляйте по `wallpaperScreenOn`.
- Если обои задуманы как экономные, поставьте `"isLite": true` — пользователи фильтруют
  каталог по этому признаку.

## 12. Ограничения движка

`WebView` в живых обоях не присоединён к окну и рисуется в поверхность вручную. Отсюда набор
особенностей, которых нет в обычном браузере.

### Программный рендеринг

По умолчанию страница растеризуется процессором. Это надёжно работает для DOM, CSS-анимаций,
2D-канваса и SVG. Но содержимое, которое обычно выводится через отдельный слой композитора,
может не попасть в кадр:

- `<video>` — движок автоматически подменяет видео на `canvas` и покадрово копирует туда
  изображение. Полифилл включается сам, ничего делать не нужно. Помните, что копирование
  каждого кадра стоит процессорного времени.
- WebGL, `backdrop-filter`, `mix-blend-mode` и подобные эффекты композитора — проверяйте
  на устройстве, поведение зависит от версии System WebView.

Режим «Аппаратный рендер» в настройках включает отрисовку через GPU. Он экспериментальный:
на части прошивок `WebView` не отдаёт содержимое в аппаратный канвас, и обои становятся
чёрными. Движок проверяет это сам при запуске и при неудаче откатывается на процессор,
показывая предупреждение в настройках.

### Размеры и вьюпорт

Страница получает размер поверхности обоев. `window.innerWidth` и `innerHeight` возвращают
CSS-пиксели, `devicePixelRatio` — плотность экрана.

Задавайте высоту явно. Конструкция `height: 100%` работает только если высота задана всей
цепочке от корня:

```css
html, body { height: 100%; margin: 0; }
```

Либо используйте `100vh`, либо `position: fixed; inset: 0`.

### Прочее

- Обои работают в одном процессе с приложением.
- `localStorage` и `sessionStorage` доступны, домен один: `127.0.0.1` с текущим портом.
  Поскольку порт может меняться между запусками, **не полагайтесь на `localStorage`
  для важных данных** — используйте `saveSetting`.
- Нет доступа к камере, микрофону и геолокации.
- Диалоги `alert` в обоях подавляются.
- Открывать внешние ссылки некуда: страница обоев не может запустить браузер.

## 13. Гироскоп и параллакс

Поток данных акселерометра включается только при `"useGyroscope": true` в манифесте. Без этого
флага сенсор не регистрируется и батарея не тратится.

События приходят не чаще чем раз в 33 миллисекунды, то есть около 30 раз в секунду, и только
пока экран включён и обои видимы.

```js
window.addEventListener('wallpaperGyroscope', (e) => {
  const { pitch, roll, x, y, z } = e.detail;
  // x, y, z — сырые значения акселерометра в м/с²,
  // диапазон примерно от -9.8 до 9.8
  // pitch дублирует y, roll дублирует x
  const dx = Math.max(-1, Math.min(1, roll / 9.8));
  const dy = Math.max(-1, Math.min(1, pitch / 9.8));
  layer.style.transform = `translate(${dx * 20}px, ${dy * 20}px)`;
});
```

Сглаживайте значения, иначе картинка будет дрожать:

```js
let sx = 0, sy = 0;
window.addEventListener('wallpaperGyroscope', (e) => {
  sx += (e.detail.roll  - sx) * 0.15;
  sy += (e.detail.pitch - sy) * 0.15;
});
```

### Пролистывание рабочих столов

Отдельное событие, не требующее разрешений и флагов:

```js
window.addEventListener('wallpaperOffset', (e) => {
  const { xOffset, yOffset } = e.detail;  // от 0.0 до 1.0
  bg.style.transform = `translateX(${-xOffset * 200}px)`;
});
```

Событие приходит только на реальном рабочем столе. В превью внутри приложения его нет —
не завязывайте на него первичную раскладку сцены, иначе в превью ничего не отрисуется.

## 14. Совместимость версий

Поле `minAppVersion` задаёт требование к версии Wallify. Если оно не выполнено, комплект
показывается в списке с предупреждением, а кнопка применения блокируется.

| Запись | Значение |
|---|---|
| `1.2.0` | не ниже 1.2.0, эквивалент `>=1.2.0` |
| `>=1.2.0` | не ниже 1.2.0 |
| `>1.2.0` | строго выше |
| `<=1.2.0` | не выше |
| `<1.2.0` | строго ниже |
| `==1.2.0` | ровно эта версия |

Версии сравниваются как `major.minor.patch`, отсутствующие компоненты считаются нулями.
Нечисловые символы отбрасываются. Если разобрать требование не удалось, комплект считается
совместимым — движок не блокирует обои из-за собственной ошибки разбора.

## 15. Упаковка и распространение

### Архив

Комплект распространяется обычным ZIP-архивом. Расширение `.zip` или `.wallify`.

```
my-wallpaper.zip
├── manifest.json
├── index.html
└── assets/…
```

Допускается и вариант с одной общей папкой внутри — при установке она срезается:

```
my-wallpaper.zip
└── my-wallpaper/
    ├── manifest.json
    └── index.html
```

Правила установки:

- Архив обязан содержать `index.html` или файл, указанный в `main`, на верхнем уровне
  (после срезания общей папки). Иначе импорт отклоняется.
- Имя папки берётся из `manifest.name` и очищается от символов, недопустимых в именах файлов.
- Если папка с таким именем уже есть, файлы перезаписываются. Так работает обновление.
- Служебные записи `__MACOSX/` и `.DS_Store` пропускаются.
- Пути с `..` игнорируются.

### Установка пользователем

Три равноценных способа:

1. Открыть `.zip` или `.wallify` из любого файлового менеджера или из загрузок — Wallify
   предложит себя, покажет карточку с именем, автором, версией и числом файлов и предложит
   установить сразу с применением.
2. Отправить архив в Wallify через системное «Поделиться».
3. Кнопка импорта на вкладке «Обои» в приложении.

### Экспорт

Кнопка «Поделиться архивом» в развёрнутой карточке собирает папку комплекта в ZIP и передаёт
его в системное меню отправки. Включается всё содержимое папки, в том числе `user_files/`.

## 16. Онлайн-каталог

Каталог живёт в открытом репозитории. Корневой файл `index.json` описывает все комплекты:

```json
{
  "version": 1,
  "updatedAt": "2026-07-26T00:00:00Z",
  "wallpapers": [
    {
      "id": "m3-shapes-dynamic",
      "name": "Material 3 Shapes",
      "author": "Rooni",
      "version": "1.2.0",
      "description": "Плавающие фигуры в палитре системы",
      "path": "wallpapers/m3-shapes-dynamic",
      "main": "index.html",
      "useGyroscope": false,
      "isLite": false,
      "stars": 42,
      "createdAt": "2026-01-10T00:00:00Z",
      "updatedAt": "2026-07-01T00:00:00Z",
      "downloadUrl": "https://example.com/m3-shapes-dynamic.zip"
    }
  ]
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный идентификатор |
| `name` | да | Название, оно же имя папки при установке |
| `author` | да | Автор |
| `version` | да | Версия, сравнивается с установленной для показа обновлений |
| `description` | да | Краткое описание |
| `path` | да | Путь к папке комплекта внутри репозитория |
| `main` | нет | Точка входа, по умолчанию `index.html` |
| `isLite` | нет | Влияет на фильтр в каталоге |
| `stars` | нет | Используется для сортировки по популярности |
| `downloadUrl` | нет | Прямая ссылка на архив |

**Указывайте `downloadUrl`.** Если он есть, приложение скачивает и распаковывает архив целиком.
Без него оно может забрать только `main` и `manifest.json` напрямую из репозитория — обои
с картинками, шрифтами и отдельными скриптами приедут неполными.

### README.md

Файл `README.md` рядом с комплектом показывается на странице комплекта в каталоге.
Поддерживается ограниченное подмножество разметки:

- заголовки `#`, `##`, `###`;
- жирный текст `**текст**`;
- моноширинный `` `код` ``;
- абзацы, разделённые пустой строкой.

HTML в README экранируется по соображениям безопасности: содержимое приходит из чужого
репозитория и не должно выполняться.

## 17. Отладка

### Логи

Движок и превью пересылают консоль страницы в системный лог под тегом `WallifyJS`.
Туда же попадают HTTP-ошибки локального сервера — это самый быстрый способ найти
ненайденный файл.

```
adb logcat -c
adb logcat WallifyJS:V *:S
```

В логе вы увидите обычные `console.log`, `console.warn`, `console.error` и строки вида:

```
W WallifyJS: HTTP 404 for http://127.0.0.1:35183/assets/missing.png
```

### Снимок состояния страницы

Через полторы секунды после загрузки движок автоматически печатает строку `WALLIFY_DIAG`:

```
WALLIFY_DIAG env=engine | viewport=411x905 | dpr=2.625 | body=411x905 | raf=67 |
engine=yes | canvasCount=1 | canvas0 at=0,0 size=411x905 buf=863x1900
vis=visible disp=block opacity=1 | svgCount=0 | imgCount=0 | videoCount=0
```

Что смотреть:

| Показатель | О чём говорит |
|---|---|
| `env` | `engine` — живые обои, `preview` — превью в приложении |
| `viewport` | Размер вьюпорта в CSS-пикселях |
| `body` | Реальный размер `document.body`. Нулевая высота — самая частая причина пустого экрана |
| `raf` | Сколько кадров успел отрисовать `requestAnimationFrame`. Ноль означает мёртвый цикл анимации |
| `engine` | Внедрён ли мост |
| `size` у элемента | Размер на экране. `0x0` — элемент не получил габаритов |
| `buf` у canvas | Размер буфера канваса, атрибуты `width` и `height` |
| `at` | Положение на экране. Большие или отрицательные значения — элемент уехал за пределы |

Строка печатается и в обоях, и в превью, поэтому две записи можно сравнить напрямую и сразу
увидеть, где расходится поведение.

### Отладка в браузере

Пишите страницу так, чтобы она открывалась и в обычном браузере: проверяйте наличие
`window.WallpaperEngine` и подставляйте значения по умолчанию. Тогда основную часть работы
можно вести в десктопных инструментах разработчика, а на устройстве только проверять
интеграцию.

### Превью в приложении

В развёрнутой карточке комплекта есть кнопка превью. Она открывает обои на весь экран
с настоящим мостом, гироскопом и касаниями, но без установки в систему. Кнопка замка
в правом верхнем углу переключает `isUnlocked` и присылает соответствующие события —
так можно проверить поведение на экране блокировки, не блокируя устройство.

## 18. Частые ошибки

**Пустой экран, виден только фон.**
Чаще всего у `body` нулевая высота, а содержимое растянуто в процентах. Проверьте `body`
в строке `WALLIFY_DIAG`. Лечится добавлением `html, body { height: 100% }`.

**Скрипт падает на первой строке.**
Обращение к `window.WallpaperEngine` до события `wallpaperEngineReady`. Моста ещё нет.

**Анимация не возобновляется после паузы.**
Из цикла вышли по `return`, не запланировав следующий кадр, и не перезапустили его
в обработчике `wallpaperResume`.

**Настройки не читаются.**
`getSetting` всегда возвращает строку. `"0"`, `"false"` и `"null"` — истинные значения
в JavaScript. Приводите типы явно.

**Ресурс не находится.**
Проверьте регистр и путь. Сервер сопоставляет имена без учёта регистра, но путь должен быть
относительно папки комплекта, а не абсолютным путём файловой системы.

**Обои занимают сотни мегабайт хранилища.**
Картинки сохранены в настройки как `data:`-URL. Используйте `importFile` и относительные пути.

**Всё работает в превью, но не на рабочем столе, или наоборот.**
Сравните две строки `WALLIFY_DIAG`. Типичная причина — завязка на событие, которого нет
в одном из окружений: `wallpaperOffset` не приходит в превью, а системный предпросмотр
присылает `screen: "preview"`.

**Не приходят данные с внешнего API.**
Смотрите лог: скорее всего CORS. Если в настройках приложения включён экспериментальный
«Обход защиты iframe», он влияет только на загрузку встраиваемых страниц и не должен
затрагивать `fetch`.

## 19. Чек-лист перед публикацией

**Обязательное**

- [ ] `manifest.json` заполнен: `name`, `description`, `author`, `version`
- [ ] `index.html` лежит в корне комплекта
- [ ] Есть `cover.jpg` или `cover.png` — карточка без обложки выглядит пустой
- [ ] Страница не падает без `window.WallpaperEngine`
- [ ] Обработаны `wallpaperPause` и `wallpaperResume`

**Качество**

- [ ] Цвета берутся из `accentColors`, а не зашиты
- [ ] Проверено в светлой и тёмной теме
- [ ] Проверено на заблокированном экране, кнопкой замка в превью
- [ ] Анимация считает время через дельту, а не через число кадров
- [ ] Проверено при качестве рендеринга 50 % — тонкие линии не пропали
- [ ] `"useGyroscope": true` стоит только если гироскоп действительно используется
- [ ] `"isLite": true` стоит, если обои действительно экономные

**Настройки**

- [ ] Если есть `settings/index.html`, все значения читаются с запасными вариантами
- [ ] Пользовательские файлы сохраняются относительными путями через `importFile`

**Публикация**

- [ ] Архив собран правильно, `index.html` доступен на верхнем уровне
- [ ] Архив установлен на чистое устройство и проверен
- [ ] Для каталога указан `downloadUrl`
- [ ] Написан `README.md`
